PR 병합은 계속 사용자가 직접 함(2026-11-17 확인).** Phase 3의 AI 요약·Bull/Bear는 아직. Phase 2는 API 키 대신 Claude 구독 예약 작업으로 하기로 정함(미국 뉴스가 몰리는 시간에 하루 4번). 예약 작업 생성과 ai-results 브랜치 저장은 사용자 승인 후 연결. 정한 것: 보유 종목·포트폴리오는 넣지 않음(공개 저장소), 화면 기본값(밝은 화면, 한국식 색)은 그대로, 사용자는 Anthropic API 키를 가급적 만들지 않으려 함 → AI가 필요 없는 기능부터 만들고, AI 부분(뉴스 분류, 요약, Bull/Bear, 템플릿 답, 문장 스크리너)은 API 키 또는 Claude 구독 예약 작업 중 무엇으로 할지 사용자가 정해야 함. AI 결과 파일은 누가 만들든 같은 형식으로 설계하기로 함. API 키 없이 생기는 제약: 버튼을 눌러 즉석 실행하는 AI(새 템플릿 실행, 문장 스크리너)는 불가, 예약 작업은 하루 1~2번·구독 사용량 안에서만.

**일하는 방식 (사용자와 정한 것)**
- 기능은 하나씩 붙이고, 붙일 때마다 실제 데이터로 화면을 확인해 스크린샷을 보여 줍니다.
- 작업 브랜치에 올린 뒤 사용자가 "PR 만들어"라고 하면 PR을 만들고, 사용자가 Merge를 누르면 배포를 확인합니다. `main` 에 직접 올리지 않습니다.
- 사용자는 한국어 존댓말, 쉬운 말, 간결한 정리를 원합니다. 못 하는 일은 이유와 필요한 조치를 함께 설명합니다.
- 제가 정한 기준값(국면 판단, 차트 체크리스트, 부채 신호등, 묶음 구성 등)과 확인하지 못한 부분은 숨기지 않고 알립니다.
- 저장소가 공개이므로 노션의 글(유료 구독 콘텐츠 정리와 개인 메모 포함)이나 보유 수량 같은 개인 정보는 넣지 않습니다.
- **유료 구독 글을 녹이는 방식 (2026-11-17 사용자 결정)**: 사용자가 준 유료 글 정리(예: 아이렌 관점 PDF)는 저장소·사이트에 옮기지 않습니다. 그 글이 '무엇을 보는지'만 틀로 삼아 항목을 고르고, 숫자와 문장은 SEC 공시·회사 보도자료·시세로 직접 채웁니다(`config/thesis.json`). 작가 이름, 목표가, 매매 기록, 발언 인용은 넣지 않습니다. 원문을 사용자 기기에만 저장해 보는 방식(파일 불러오기 → 브라우저에만 저장)은 사용자가 원하면 나중에 붙입니다.
- 봇 차단을 우회하지 않습니다(CNN Fear & Greed를 자체 계산으로 대체한 이유).

**확인이 남은 것**
- **예약 실행 간격**: 30분 간격 설정인데 2026-11-15(일)에는 4~7시간에 한 번만 돌았습니다(GitHub가 무료 예약 실행을 미루는 것). 사용자와 "며칠 지켜보고, 평일에도 나아지지 않으면 알린다"고 정했습니다. Actions 실행 기록에서 평일의 예약 실행(event=schedule) 간격을 확인하고, 여전히 몇 시간씩 벌어지면 외부 무료 서비스(cron-job.org 등)가 30분마다 `workflow_dispatch` 로 깨우는 방법을 안내합니다. GitHub 토큰은 사용자가 직접 발급·등록해야 합니다.
- **종목별 뉴스 거르기**: Yahoo가 '관련 종목'을 느슨하게 붙여서, 제목에 회사 이름·티커가 들어간 기사를 먼저 고르게 했습니다. 이름이 흔한 단어인 종목을 새로 넣으면 엉뚱한 기사가 섞일 수 있어 화면을 한 번 봐야 합니다.
- **트레이딩뷰 위젯**: 작업 환경에서 트레이딩뷰에 접속할 수 없어 실제로 그려지는지 확인하지 못했습니다. 사용자 확인이 필요합니다.
- **RSI·CCI 값**: 계산식은 트레이딩뷰 기본과 같지만 값 대조는 하지 못했습니다.
- **예약 실행 유지 장치**: 60일이 지나야 효과를 확인할 수 있습니다.
- **뉴스 분류 예약 작업**: 2026-11-17 사용자가 예약 작업 설정에 저장소를 연결해 저장(403) 문제 해결. 시험 실행에서 17건 분류 → `ai-results` 푸시 → kick.yml → 사이트 갱신까지 확인(사이트 121건). 남은 것: `news_ai.py check` 가 지난 결과에 있는 기사를 출처로 단 요약 문장을 '출처 없음'으로 거르는 점(merge 단계에서는 남음) — 고칠지 정해야 함.
- **회사 소개 (AI)**: 첫 13종목은 2026-11-17 대화에서 Claude가 SEC 10-K·20-F, 최근 실적 보도자료, Yahoo 회사 프로필(경영진)을 읽고 씀(`ai-results` 의 `profiles.json`). 회사 누리집은 작업 환경에서 막혀 못 읽음. 엔비디아는 Yahoo 경영진 목록이 비어 CEO만 적음. 로켓랩은 부문별 매출을 못 찾아 비중 없음, 네비우스는 실적 보도자료가 없어 매출 구성 없음, 한국 2종목은 DART 미연결이라 Yahoo 프로필만(매출 구성·비전 없음). 예약 작업이 새 정기 보고서가 나온 종목을 다시 쓰는 흐름은 PR 병합 뒤 첫 실행에서 확인해야 함. 휴대폰에서는 칸이 길다는 의견이 나오면 접기를 검토.

**새 대화에서 작업을 확인하는 법**
- `pip install -r scripts/requirements.txt` 후 `python scripts/fetch_data.py --prev site/data/dashboard.json` 으로 수집하고, `python -m http.server --directory site` 로 띄워 Playwright로 PC(1280px)와 휴대폰(390px) 화면을 확인합니다. 첫 수집은 포워드 PER과 SEC 때문에 3~4분 걸리고, 같은 날 다시 돌리면 빠릅니다.

## 구조

```
config/dashboard.json   종목, 지표, 탭 배치, 국면 판단 기준값 (여기만 고치면 됩니다)
config/manual.json      직접 입력하는 값과 일정
config/thesis.json      투자 논리 점검판(공개 자료로 확인한 사실·일정·논리와 반대 관점, 출처)
config/glossary.json    지표 이름 옆 물음표 설명
scripts/fetch_data.py   설정을 읽어 데이터를 받고 site/data/dashboard.json 으로 저장
site/                   화면 (index.html, style.css, app.js). 저장된 JSON만 읽습니다
.github/workflows/update.yml   30분마다 수집 → GitHub Pages 배포
.github/workflows/watchlist.yml   종목 추가·삭제 요청 처리
scripts/watchlist.py    요청 제목을 읽어 관심 종목을 고침
scripts/sec.py          SEC 공시에서 공시 목록, 내부자 매매, 13F를 받음
scripts/financials.py   SEC XBRL로 장기 재무(연간·분기)와 최근 실적 보도자료를 받음
scripts/ai_export.py    종목별 AI 분석용 파일(site/data/ai/)을 만듦
scripts/thesis.py       투자 논리 점검판의 숫자(시가총액 대비 현금·잔고·ARR, 희석, 경쟁사 비교)를 계산
```

흐름: 설정 파일 → 수집 스크립트 → `site/data/dashboard.json`(화면용), `site/data/history.json`(차트 이력), `site/data/financials.json`(장기 재무 원본, 하루 한 번), `site/data/ai/`(AI용 종목 파일) → 화면. 수집 결과는 저장소에 올리지 않고 배포할 때마다 새로 만듭니다.

## 자주 하는 수정

- **종목 추가·삭제**: 사이트 종목 탭의 "종목 추가" 칸에 티커를 적고 요청을 보내면 1~3분 뒤 반영됩니다(삭제는 목록 편집의 "삭제 요청"). 요청은 GitHub 이슈로 만들어지고, `.github/workflows/watchlist.yml` 이 저장소 주인의 요청만 받아 `scripts/watchlist.py` 로 설정 파일을 고친 뒤 다시 배포합니다. 직접 고치려면 `config/dashboard.json` 의 `watchlist` 에 한 줄을 넣거나 지웁니다(한국 종목은 `005930.KS`, 코스닥은 `.KQ`).
- **지표 추가**: `series` 에 한 줄을 넣고(`"source": "yahoo"` 는 `symbol`, `"source": "fred"` 는 `id`), 보여줄 탭의 `sections[].items` 에 그 이름을 넣습니다. FRED 지표는 `freq`(M·Q·W)와 `transform`(`yoy` 전년 대비, `mom_pct` 전월 대비 %, `mom_diff` 전월 대비 증감)을 쓸 수 있고, `event` 를 적으면 다음 발표일이 일정에 들어갑니다.
- **물음표 설명 추가·수정**: `config/glossary.json` 의 `terms` 에 항목을 넣고, 지표(`series`)에는 `"help": "항목 이름"` 을 적습니다. 종목 요약의 항목은 `site/app.js` 의 `HELP_BY_LABEL` 에서 연결합니다.
- **직접 입력 값**: `config/manual.json` 의 `values` 에 값과 입력한 날짜(`entered`)를 적습니다.
- **국면 판단 기준 변경**: `regime` 의 숫자를 고칩니다. 화면의 "판단 기준 보기"에 그대로 반영됩니다.
- **종목별 뉴스 검색어**: `watchlist` 의 종목 줄에 `"news_q"`(검색어, 한국 종목은 영문 회사명이 필요), `"news_keywords"`(제목에서 찾을 이름), `"news_match"`(Yahoo의 다른 티커, 예: SK하이닉스의 SKHY)를 적습니다. 사이트에서 한국 종목을 추가하면 `news_q` 는 자동으로 들어갑니다.
- **종목별 링크**: `watchlist` 의 종목 줄에 `"ir": "https://…"`, `"notion": "https://…"` 를 적으면 바로가기에 IR 페이지와 노션 노트가 나옵니다.
- **직접 적는 일정**: `config/manual.json` 의 `events` 에 `{ "date": "2026-12-01", "title": "…", "kind": "내 이벤트" }` 를 넣습니다.
- **FOMC 날짜**: 연준 공식 일정 페이지에서 하루 한 번 자동으로 읽습니다. `calendar.fomc` 는 읽기에 실패했을 때만 쓰는 예비 값입니다.

설계서와 다르게 처리한 것:

- **Fear & Greed**: CNN이 자동 수집을 차단해서 받지 않습니다. 대신 같은 취지의 "심리 지수 (자체 계산)"를 씁니다. 모멘텀, 변동성, 안전자산 수요, 시장 폭, 정크본드 수요 다섯 가지가 최근 1년 중 어느 위치인지(백분위)를 평균한 0~100 값이며, CNN 값과 숫자가 같지 않습니다.
- **시장 폭**: 개별 종목 500개를 30분마다 받는 대신 11개 섹터 ETF 중 200일선 위에 있는 개수로 봅니다.
- **경제지표 발표일**: FRED 지표 페이지의 "Next Release Date"를 읽습니다. 키가 필요 없고, 날짜가 지났을 때만 다시 받습니다.
- **CPI 전년 대비**: 2025년 10월 CPI는 발표되지 않아, 2026년 10월 값은 앞뒤 달로 추정한 1년 전 값과 비교합니다. 화면에 추정이라고 표시합니다.
- **한국은행 기준금리**: 무료 자동 수집 경로가 없어 `config/manual.json` 에 직접 적습니다. 한국은행 ECOS API 키(무료)를 받으면 자동화할 수 있습니다.
- **한국 수출액**: FRED의 OECD 집계를 쓰며 2~3개월 늦습니다.

- **실적 추이**: Yahoo 무료 데이터는 최근 4~5개 분기만 줍니다(설계서는 8분기). 매출 예상치 대비 실제도 무료 데이터가 없습니다. 미국 종목은 아래 "장기 재무"로 보완합니다.
- **장기 재무 (SEC)**: 회사가 XBRL에 적은 표준 항목 이름으로 읽습니다. 항목 이름은 회사·기간마다 달라 여러 이름을 순서대로 찾고, 회사가 자체 이름을 쓴 기간은 비어 있습니다(예: 엔비디아 FY21 이전 설비투자 → FCF 빈칸). 현금흐름 분기 값은 누적값의 차이로, 4분기는 연간 − 9개월 누적으로 만들고, 4분기 EPS는 만들지 않습니다. 옛 EPS·주식 수는 Yahoo의 주식 분할 이력으로 보정합니다. 외국 기업(20-F, 예: 네비우스)은 연간만 있습니다. 상장 전 기간은 없습니다(코어위브 2023년~, 스페이스X 2025년~). 한국 종목은 SEC 자료가 없습니다.
- **ROIC (직접 정한 기준)**: 세후 영업이익 ÷ 투하자본. 세후 영업이익 = 영업이익 × (1 − 실효 세율, 0~50% 밖이면 21%). 투하자본 = 자기자본 + 차입금 − 현금 − 단기 투자자산(기초·기말 평균). 투하자본이 0 이하이거나 총자산의 10% 미만이면 값이 튀어 비웁니다(예: 팔란티어). 차입금에 리스 부채는 넣지 않습니다.
- **회사 소개 (AI, `scripts/profiles.py`)**: Claude가 공시·보도자료·Yahoo 프로필을 읽고 쓴 소개를 `ai-results` 의 `profiles.json` 에 두고, 30분 갱신이 검사해 붙임. 검사: 문장·매출 항목·경영진마다 출처 번호가 있어야 하고, 출처 주소가 http(s)여야 하며, 매출 비중 합계가 101%를 넘으면 비중을 지움. 다시 쓸 종목(`data/profile_queue.json`): 소개 없음, 소개 뒤 새 10-K·10-Q·20-F, 또는 100일 경과(대시보드가 정한 값).
- **조건 스크리너 (AI 아님, `scripts/screener.py`)**: 종목 목록은 위키백과 'List of NASDAQ-100 companies' 표(7일에 한 번, 실패하면 이전 목록), 숫자는 Yahoo 종목 요약(info) 값 그대로(Yahoo 정의, 예: 매출 성장률은 최근 분기의 전년 동기 대비), 수익률·52주 고점 대비·200일선 대비는 일봉 1년치로 계산, 배당수익률 = 연 배당금 ÷ 현재가. 하루 한 번 받고(첫 실행에 약 2분 더 걸림) 실패한 종목은 이전 값을 쓰고 다음 실행에 다시 받음. 배수(PER 등)가 0 이하면 '적자'로 보고 조건에서 뺌. 예시 조건(성장 + 적정 가격: 매출 성장 20% 이상·선행 PER 35 이하, 고퀄리티: ROE 20%·영업이익률 25% 이상·부채비율 100 이하, 현금 창출: FCF 수익률 4% 이상, 낙폭 과대: 고점 대비 −30% 이하, 추세 강함: 200일선 위·3개월 +10% 이상)은 대시보드가 정한 값. 작업 환경에서 연속으로 받으면 Yahoo가 잠시 막는 일(401)이 있었음 — Actions에서 막히면 실패 종목 수가 늘어나는지 확인.
- **가치 계산기 (AI 아님, 브라우저에서 계산 `site/app.js` calcBody)**: 기준 값 = SEC 최근 4개 분기 FCF 또는 순이익(한국 종목은 Yahoo 분기 FCF 4개 합계), 주식보상비용 빼기 선택. DCF는 10년 2단계(1~5년, 6~10년)와 영구가치, 순현금을 더해 주식 수(시가총액 ÷ 주가)로 나눔. 역DCF는 10년 성장률을 하나로 두고 지금 시가총액과 맞는 값을 이분법으로 찾음. IRR = (N년 뒤 주당순이익 × 매도 P/E ÷ 지금 주가)^(1/N) − 1, 배당 제외. 기본값은 대시보드가 정한 값: 할인율 10%, 영구 3%, 1~5년 = 매출 3년 CAGR을 0~30%로 자른 값, 6~10년 = 그 절반, 매도 P/E = 지금 P/E와 5년 중앙값 중 작은 값(최대 40배, 없으면 20배). 기준 값이 0 이하면 DCF를 내지 않음.

  - 미룬 이유: 비용은 무료 범위지만 Cloudflare 계정 관리, 고장 지점 추가, 주소 공개에 따른 남용 방지 장치가 필요해 당장은 복잡하다.
  - 넣는 시점: "종목 추가"의 1~3분 대기가 실제로 불편해지면.
  - 넣을 때: 종목을 관심 목록에 저장하는 부분(GitHub 요청 방식)은 그대로 두고, 미리보기와 검색만 서버 위에 얹는다. 배포는 사용자가 직접 하거나 Cloudflare 권한을 따로 연결해야 한다.

- **텔레그램 실시간 알림** — 2026-11-15 결정: 지금은 클로드 브리핑(하루 두 번)만 쓰고, 장중 급변을 30분 안에 토큰 없이 받고 싶어지면 넣는다.
  - 넣을 때: 갱신 워크플로에 "이번 실행에서 새로 생긴 알림(`alerts` 중 `at` 이 이번 `generated_at` 과 같은 것)을 텔레그램 봇으로 보내기" 단계 하나만 추가한다. 봇 토큰과 채팅 ID는 GitHub Secrets에 넣는다. 알림 계산은 이미 되어 있다.

- **투자 논리 점검판 넓히기** — 2026-11-17: 아이렌만 먼저 만들었습니다. 다른 종목은 `config/thesis.json` 에 같은 형식으로 적으면 바로 나옵니다. 사용자가 원하면 (1) 유료 글 원문을 사용자 기기에만 저장해 점검판 옆에 보는 기능, (2) 새 실적 보도자료가 나오면 예약 작업이 `thesis.json` 의 사실·일정을 고칠 초안을 만드는 흐름을 붙입니다.

### 1차에서 남은 것

- 한국은행 기준금리 자동화 (지금은 직접 입력. 한국은행 ECOS API 키가 있으면 자동화 가능)
- IR 페이지 주소가 확인되지 않은 종목의 `ir` 링크 채우기 (지금은 코어위브, 아이렌, 삼성전자만 있고 나머지는 회사 홈페이지로 연결)

### 그다음

- 확장 계획 Phase 2~7 (위 "새 대화에서 이어가기" 참고). AI가 필요 없는 부분 중 남은 것: Phase 6 계산기와 조건 스크리너, Phase 7. 무료 데이터가 없어 못 하는 것: 매출 예상치 대비 beat/miss, 컨퍼런스콜 녹취록. 한국 종목 공시·재무는 DART 키 필요.
- AI 활용 3단계(검토): 실적 발표 다음 날 Claude 예약 작업이 AI용 파일을 읽고 실적 리뷰를 노션에 비공개로 저장, Claude 스킬로 분석 틀 고정. 필요해지면 MCP 커넥터 서버(관심 종목 밖 회사 조회, 조건 검색).
- 한국 종목 장기 재무: 금융감독원 DART API 키(무료, 사용자가 발급해 GitHub Secrets에 등록)가 있으면 붙일 수 있습니다.

- 2차: 큰손·유동성 탭의 남은 항목(ETF 자금 흐름과 외국인·기관 순매수는 무료 출처를 찾아야 함. 한국 종목 공시는 DART API 키가 있으면 가능), 산업 탭의 남은 항목(D램 현물 가격, 반도체 수출액, PDUFA·임상 일정, IPO 캘린더), 한국어 뉴스(지금은 Yahoo의 영어 기사만. 구글 뉴스 RSS 등을 쓰려면 작업 환경에 호스트 추가 승인이 필요)
- 3차: 내 기록 탭

## 원칙

- 기능은 하나씩 붙이고, 붙일 때마다 화면을 확인하고 변경 기록을 남깁니다.
- 한 종목·지표 수집이 실패해도 나머지는 정상 표시합니다. 실패한 항목은 직전 배포의 값을 "이전 값"으로 표시합니다.
- 비밀값은 코드에 쓰지 않고 GitHub Secrets에 넣습니다. 실제 계좌 정보는 넣지 않습니다.
- 보유 수량 같은 개인 기록은 저장소가 아니라 브라우저에만 저장합니다.

## 배포

`main` 브랜치에서 `.github/workflows/update.yml` 이 매시 7분과 37분에 실행됩니다. 저장소 Settings → Pages → Source 가 "GitHub Actions" 여야 합니다. GitHub 예약 실행은 몇 분에서 수십 분 늦을 수 있습니다. 공개 저장소는 60일 동안 변경이 없으면 예약 실행이 꺼지는데, 이를 막으려고 예약 실행 때마다 워크플로를 "켜기"로 다시 지정합니다. 그래도 꺼졌다면 Actions 탭에서 다시 켭니다.
