# invest-dashboard

흩어진 투자 정보를 한 화면에 모아 보는 개인용 대시보드입니다. 실제 시장 데이터를 30분마다 자동으로 받아 GitHub Pages에 올립니다. 혼자 쓰는 용도이고, 모든 신호는 참고용 점검 알림입니다.

## 새 대화에서 이어가기 (2026-11-16 기준)

새 대화를 시작한 Claude는 이 묶음과 아래 "나중에 할 일"을 먼저 읽습니다.

**지금 상태**
- 사이트: https://lwindowy.github.io/invest-dashboard/ (GitHub Pages, `main` 에서 배포)
- 일곱 탭 중 여섯 개가 동작합니다: 홈, 거시경제, 종목, 캘린더, 큰손·유동성, 산업. "내 기록"(3차)만 자리만 있습니다.
- 수집은 실패 0건으로 돌고 있습니다(지표 55개, 관심 종목 13개).

**일하는 방식 (사용자와 정한 것)**
- 기능은 하나씩 붙이고, 붙일 때마다 실제 데이터로 화면을 확인해 스크린샷을 보여 줍니다.
- 작업 브랜치에 올린 뒤 사용자가 "PR 만들어"라고 하면 PR을 만들고, 사용자가 Merge를 누르면 배포를 확인합니다. `main` 에 직접 올리지 않습니다.
- 사용자는 한국어 존댓말, 쉬운 말, 간결한 정리를 원합니다. 못 하는 일은 이유와 필요한 조치를 함께 설명합니다.
- 제가 정한 기준값(국면 판단, 차트 체크리스트, 부채 신호등, 묶음 구성 등)과 확인하지 못한 부분은 숨기지 않고 알립니다.
- 저장소가 공개이므로 노션의 글(유료 구독 콘텐츠 정리와 개인 메모 포함)이나 보유 수량 같은 개인 정보는 넣지 않습니다.
- 봇 차단을 우회하지 않습니다(CNN Fear & Greed를 자체 계산으로 대체한 이유).

**저장소 밖에 있는 것 (코드에 안 보임)**
- 클로드 예약 작업 "투자 대시보드 브리핑": 월~토 오전 7:17과 오후 4:17(한국 시간), Sonnet, 클로드 앱 푸시. `data/brief.json` 을 읽고 뉴스를 확인해 알릴 것이 있을 때만 보냅니다. 첫 실행은 2026-11-16 아침이며, 길이·내용에 대한 사용자 의견을 아직 받지 못했습니다.
- 클로드 클라우드 환경 `invest-dashboard`: 데이터 출처 호스트(Yahoo, FRED, 연준, 위키백과, CFTC, SEC, GitHub Pages)를 허용해 둔 작업 환경입니다. 새 출처를 쓰려면 호스트 추가 승인이 필요합니다.
- 사용자의 노션: 「용어·지표」, 「차트 분석」, 「기업분석」 페이지를 참고했습니다.

**확인이 남은 것**
- **예약 실행 간격**: 30분 간격 설정인데 2026-11-15(일)에는 4~7시간에 한 번만 돌았습니다(GitHub가 무료 예약 실행을 미루는 것). 사용자와 "며칠 지켜보고, 평일에도 나아지지 않으면 알린다"고 정했습니다. Actions 실행 기록에서 평일의 예약 실행(event=schedule) 간격을 확인하고, 여전히 몇 시간씩 벌어지면 외부 무료 서비스(cron-job.org 등)가 30분마다 `workflow_dispatch` 로 깨우는 방법을 안내합니다. GitHub 토큰은 사용자가 직접 발급·등록해야 합니다.
- **종목별 뉴스 거르기**: Yahoo가 '관련 종목'을 느슨하게 붙여서, 제목에 회사 이름·티커가 들어간 기사를 먼저 고르게 했습니다. 이름이 흔한 단어인 종목을 새로 넣으면 엉뚱한 기사가 섞일 수 있어 화면을 한 번 봐야 합니다.
- **트레이딩뷰 위젯**: 작업 환경에서 트레이딩뷰에 접속할 수 없어 실제로 그려지는지 확인하지 못했습니다. 사용자 확인이 필요합니다.
- **RSI·CCI 값**: 계산식은 트레이딩뷰 기본과 같지만 값 대조는 하지 못했습니다.
- **예약 실행 유지 장치**: 60일이 지나야 효과를 확인할 수 있습니다.
- **실적 결과·Short Float 알림**: 실제 실적 발표가 있는 날에 처음 확인됩니다(2026-11-18 엔비디아).
- **FOMC 금리 확률**: 연방기금금리 선물(Yahoo)로 직접 계산합니다. 2026-11-13 종가 기준 12/9 회의 25bp 인상 88.6%·50bp 인상 11.4%로, 같은 날 보도된 CME FedWatch(88.5%·11.5%)와 거의 같았습니다. CME 페이지를 직접 대조하지는 못했습니다. 먼 회의는 거래가 적어 값이 거칩니다.
- **한국은행 기준금리**: 2026-11-26 금통위 결과가 나오면 `config/manual.json` 을 고쳐야 합니다.

**새 대화에서 작업을 확인하는 법**
- `pip install -r scripts/requirements.txt` 후 `python scripts/fetch_data.py --prev site/data/dashboard.json` 으로 수집하고, `python -m http.server --directory site` 로 띄워 Playwright로 PC(1280px)와 휴대폰(390px) 화면을 확인합니다. 첫 수집은 포워드 PER과 SEC 때문에 3~4분 걸리고, 같은 날 다시 돌리면 빠릅니다.

## 구조

```
config/dashboard.json   종목, 지표, 탭 배치, 국면 판단 기준값 (여기만 고치면 됩니다)
config/manual.json      직접 입력하는 값과 일정
config/glossary.json    지표 이름 옆 물음표 설명
scripts/fetch_data.py   설정을 읽어 데이터를 받고 site/data/dashboard.json 으로 저장
site/                   화면 (index.html, style.css, app.js). 저장된 JSON만 읽습니다
.github/workflows/update.yml   30분마다 수집 → GitHub Pages 배포
.github/workflows/watchlist.yml   종목 추가·삭제 요청 처리
scripts/watchlist.py    요청 제목을 읽어 관심 종목을 고침
scripts/sec.py          SEC 공시에서 공시 목록, 내부자 매매, 13F를 받음
```

흐름: 설정 파일 → 수집 스크립트 → `site/data/dashboard.json`(화면용)과 `site/data/history.json`(차트 이력) → 화면. 수집 결과는 저장소에 올리지 않고 배포할 때마다 새로 만듭니다.

## 자주 하는 수정

- **종목 추가·삭제**: 사이트 종목 탭의 "종목 추가" 칸에 티커를 적고 요청을 보내면 1~3분 뒤 반영됩니다(삭제는 목록 편집의 "삭제 요청"). 요청은 GitHub 이슈로 만들어지고, `.github/workflows/watchlist.yml` 이 저장소 주인의 요청만 받아 `scripts/watchlist.py` 로 설정 파일을 고친 뒤 다시 배포합니다. 직접 고치려면 `config/dashboard.json` 의 `watchlist` 에 한 줄을 넣거나 지웁니다(한국 종목은 `005930.KS`, 코스닥은 `.KQ`).
- **지표 추가**: `series` 에 한 줄을 넣고(`"source": "yahoo"` 는 `symbol`, `"source": "fred"` 는 `id`), 보여줄 탭의 `sections[].items` 에 그 이름을 넣습니다. FRED 지표는 `freq`(M·Q·W)와 `transform`(`yoy` 전년 대비, `mom_pct` 전월 대비 %, `mom_diff` 전월 대비 증감)을 쓸 수 있고, `event` 를 적으면 다음 발표일이 일정에 들어갑니다.
- **물음표 설명 추가·수정**: `config/glossary.json` 의 `terms` 에 항목을 넣고, 지표(`series`)에는 `"help": "항목 이름"` 을 적습니다. 종목 요약의 항목은 `site/app.js` 의 `HELP_BY_LABEL` 에서 연결합니다.
- **직접 입력 값**: `config/manual.json` 의 `values` 에 값과 입력한 날짜(`entered`)를 적습니다.
- **국면 판단 기준 변경**: `regime` 의 숫자를 고칩니다. 화면의 "판단 기준 보기"에 그대로 반영됩니다.
- **종목별 뉴스 검색어**: `watchlist` 의 종목 줄에 `"news_q"`(검색어, 한국 종목은 영문 회사명이 필요), `"news_keywords"`(제목에서 찾을 이름), `"news_match"`(Yahoo의 다른 티커, 예: SK하이닉스의 SKHY)를 적습니다. 사이트에서 한국 종목을 추가하면 `news_q` 는 자동으로 들어갑니다.
- **종목별 링크**: `watchlist` 의 종목 줄에 `"ir": "https://…"`, `"notion": "https://…"` 를 적으면 바로가기에 IR 페이지와 노션 노트가 나옵니다.
- **직접 적는 일정**: `config/manual.json` 의 `events` 에 `{ "date": "2026-12-01", "title": "…", "kind": "내 이벤트" }` 를 넣습니다.
- **FOMC 날짜**: 연준 공식 일정 페이지에서 하루 한 번 자동으로 읽습니다. `calendar.fomc` 는 읽기에 실패했을 때만 쓰는 예비 값입니다.

## 데이터 출처

| 데이터 | 출처 | 비고 |
| --- | --- | --- |
| 주가, 지수, 환율, 실적일 | Yahoo Finance (`yfinance`) | 15분가량 지연 |
| 금리, 하이일드 스프레드 | FRED 공개 CSV | 키 없이 받음. 하루 한 번 갱신, 1~2일 늦음 |
| 공시 목록, 내부자 매매, 13F | SEC EDGAR (`scripts/sec.py`) | 하루 한 번. 키 없이 받음. 미국 상장 종목만 |
| COT 선물 포지션 | CFTC 공개 데이터 (TFF, 선물만) | 매주 금요일 발표, 화요일 기준. 키 없이 받음 |
| FOMC 일정 | 연준 공식 일정 페이지 | 하루 한 번. 결정일(회의 둘째 날), 미국 날짜 |
| RSI, 이동평균, 국면 판단, 심리 지수 | 주가로 직접 계산 | RSI는 Wilder 방식(트레이딩뷰 기본과 같은 계산) |

설계서와 다르게 처리한 것:

- **Fear & Greed**: CNN이 자동 수집을 차단해서 받지 않습니다. 대신 같은 취지의 "심리 지수 (자체 계산)"를 씁니다. 모멘텀, 변동성, 안전자산 수요, 시장 폭, 정크본드 수요 다섯 가지가 최근 1년 중 어느 위치인지(백분위)를 평균한 0~100 값이며, CNN 값과 숫자가 같지 않습니다.
- **시장 폭**: 개별 종목 500개를 30분마다 받는 대신 11개 섹터 ETF 중 200일선 위에 있는 개수로 봅니다.
- **경제지표 발표일**: FRED 지표 페이지의 "Next Release Date"를 읽습니다. 키가 필요 없고, 날짜가 지났을 때만 다시 받습니다.
- **CPI 전년 대비**: 2025년 10월 CPI는 발표되지 않아, 2026년 10월 값은 앞뒤 달로 추정한 1년 전 값과 비교합니다. 화면에 추정이라고 표시합니다.
- **한국은행 기준금리**: 무료 자동 수집 경로가 없어 `config/manual.json` 에 직접 적습니다. 한국은행 ECOS API 키(무료)를 받으면 자동화할 수 있습니다.
- **한국 수출액**: FRED의 OECD 집계를 쓰며 2~3개월 늦습니다.

- **실적 추이**: Yahoo 무료 데이터는 최근 4~5개 분기만 줍니다(설계서는 8분기). 매출 예상치 대비 실제도 무료 데이터가 없습니다.
- **재무 계열 데이터**(재무 요약, 실적, 목표주가, 공매도)는 하루 한 번만 받고, 같은 날에는 직전 배포의 값을 다시 씁니다.
- **차트 체크리스트**: 노션 「차트 분석」의 세 묶음(사야 할 때, 기다려야 할 때, 팔아야 할 때)을 그대로 옮겼습니다. 골든·데드크로스는 20일선과 60일선, "최근"은 10거래일, 20일선 간격은 ±2% 이내를 횡보·±15% 초과를 과도로 봅니다. `chart_rules` 에서 바꿉니다.
- **CDS와 회사채 가격**: 개별 기업 값은 무료 데이터가 없어 넣지 않습니다. 대신 종목 요약의 "부채와 신용 위험"(이자보상배율, 순부채÷EBITDA, 부채비율, 유동비율, 1년 내 만기 부채, 분기 이자비용)과 거시경제 탭의 등급별 회사채 스프레드(투자등급, BBB, BB, B, CCC, 하이일드)로 봅니다. 신호등 기준은 `debt_rules` 에서 바꿉니다.
- **CTA 포지션**: 증권사 추정치는 기관용이라 받을 수 없습니다. COT의 Leveraged Funds(실제 신고 데이터)와, 선물 가격에서 직접 계산한 추정치(1·3·6·12개월 수익률을 변동성으로 나눈 값의 평균, −100~+100) 두 가지로 근사하고 화면에 추정치라고 표시합니다.
- **TMT 모멘텀 지수**: 기술(XLK)·통신(XLC) 섹터 ETF의 3개월 수익률에서 SPY의 3개월 수익률을 뺀 값과 QQQ÷SPY 비율로 대신합니다.
- **빅테크 설비투자**: 마이크로소프트, 알파벳, 아마존, 메타, 오라클의 분기 CAPEX를 하루 한 번 Yahoo에서 받습니다. 회계 분기가 다른 회사는 분기 말 달을 3·6·9·12월로 맞추고, 합계는 다섯 회사 모두 값이 있는 분기만 계산합니다. 회사 목록은 `capex` 에서 바꿉니다.
- **섹터 히트맵**: 보여 줄 ETF는 `heatmap` 에서 바꿉니다.
- **내부자 매매**: 공개시장 매수·매도만 셉니다(주식 보상, 옵션 행사, 증여 제외). 하루에 여러 가격으로 나눠 체결된 거래는 한 건으로 합칩니다. 미리 정한 일정(10b5-1)에 따른 매도는 "계획 매도"로 구분합니다.
- **13F**: 볼 운용사는 `sec.managers` 에 CIK 번호로 적습니다. 직전 분기와는 증권 식별번호(CUSIP 앞 6자리)로 맞춰 비교하고, 내 관심 종목은 회사 이름 앞부분으로 찾습니다. 옵션은 빼고 주식만 셉니다.
- **공시 알림**: 최근 이틀 안에 접수된 8-K, 증권 발행 신고(424B), 내부자의 공개시장 매수를 알림에 넣습니다.
- **포워드 PER**: 나스닥 100과 직접 정한 묶음(대형 기술주 7개, AI 인프라, 메모리)의 시가총액 합 ÷ 예상 순이익 합을 하루 한 번 계산합니다. 종목별 예상 순이익은 시가총액 ÷ Yahoo의 포워드 PER로 구합니다. 나스닥 100 구성 종목은 위키백과 목록에서 매일 읽습니다. 값은 매일 쌓아 자체 추이를 만들며, 이 이력은 배포된 `data/dashboard.json` 안(`valuation.history`)에 이어서 저장됩니다. 그래서 갱신 워크플로는 이전 데이터를 못 받으면 배포하지 않고 멈춥니다.
- **5년 평균 기준값**: `config/manual.json` 의 `nasdaq100_fwd_pe_5y_avg` 에 직접 적습니다. 지금 값 24.2배는 노션 「용어·지표」에 적어 둔 2026년 11월 기준 값입니다.
- **지표 차트**: 숫자 카드를 누르면 큰 차트가 열립니다. 이력은 `data/history.json` 에 따로 저장하고 처음 누를 때 받습니다.
- **지표 물음표 설명**: `config/glossary.json` 에 적은 짧은 정의가 뜹니다. 저장소가 공개라서 노션 「용어·지표」의 글(유료 콘텐츠 정리와 개인 메모 포함)은 옮기지 않고, 일반적인 정의만 새로 썼습니다. 설명 창의 링크로 노션 원문을 엽니다(본인만 열림).
- **신용등급**: `config/manual.json` 의 `ratings` 에 종목별로 적습니다(S&P, 무디스, 피치, 메모, 입력한 날짜). Claude가 기사에서 찾아 넣은 값이며, 종목을 추가하면 그 종목 등급도 찾아 넣습니다. 등급을 찾지 못한 종목은 "확인된 등급 없음"으로 표시합니다.
- **한국은행 기준금리**: `config/manual.json` 의 `values.kr_base_rate` 에 직접 적습니다. 금통위 결정이 나오면 값과 날짜를 고칩니다(다음 회의는 `events` 에 적어 둠).
- **노션 기업분석 노트 링크**: 노션 「기업분석」이 한 페이지라서 모든 종목이 같은 페이지로 연결됩니다(`site.notion_company_notes`).

## 알림과 클로드 브리핑

- **알림 계산 (GitHub, 무료)**: 30분 갱신 때 `scripts/fetch_data.py` 의 `build_alerts` 가 변화를 찾아 `alerts` 에 쌓습니다(4일치). 급등락(±5%), RSI 70·30 진입, 200일선 돌파·이탈, 골든·데드크로스, 52주 신고가·신저가, 실적 예정(오늘·내일)과 결과, Short Float 20% 돌파, 국면 판단판 변화, VIX 30 돌파, FOMC·주요 경제지표(오늘·내일). 기준 숫자는 `config/dashboard.json` 의 `alerts` 에서 바꿉니다.

- **브리핑용 요약 파일**: `data/brief.json` (시장 요약, 관심 종목, 일정, 알림). 클로드 예약 작업은 이 작은 파일만 읽습니다.

### 정해 둔 것

- **중간 서버 (Cloudflare Workers 무료 요금제)** — 2026-11-15 결정: 지금은 넣지 않고 나중에 넣는다.
  - 목적: 화면에서 종목을 검색해 누르는 즉시 값 미리보기, 한글 이름 검색. Yahoo는 브라우저에서 직접 가져가는 것을 막아서 중간 서버가 있어야 한다.
  - 미룬 이유: 비용은 무료 범위지만 Cloudflare 계정 관리, 고장 지점 추가, 주소 공개에 따른 남용 방지 장치가 필요해 당장은 복잡하다.
  - 넣는 시점: "종목 추가"의 1~3분 대기가 실제로 불편해지면.
  - 넣을 때: 종목을 관심 목록에 저장하는 부분(GitHub 요청 방식)은 그대로 두고, 미리보기와 검색만 서버 위에 얹는다. 배포는 사용자가 직접 하거나 Cloudflare 권한을 따로 연결해야 한다.

- **텔레그램 실시간 알림** — 2026-11-15 결정: 지금은 클로드 브리핑(하루 두 번)만 쓰고, 장중 급변을 30분 안에 토큰 없이 받고 싶어지면 넣는다.
  - 넣을 때: 갱신 워크플로에 "이번 실행에서 새로 생긴 알림(`alerts` 중 `at` 이 이번 `generated_at` 과 같은 것)을 텔레그램 봇으로 보내기" 단계 하나만 추가한다. 봇 토큰과 채팅 ID는 GitHub Secrets에 넣는다. 알림 계산은 이미 되어 있다.

## 원칙

- 기능은 하나씩 붙이고, 붙일 때마다 화면을 확인하고 변경 기록을 남깁니다.
- 한 종목·지표 수집이 실패해도 나머지는 정상 표시합니다. 실패한 항목은 직전 배포의 값을 "이전 값"으로 표시합니다.
- 비밀값은 코드에 쓰지 않고 GitHub Secrets에 넣습니다. 실제 계좌 정보는 넣지 않습니다.
- 보유 수량 같은 개인 기록은 저장소가 아니라 브라우저에만 저장합니다.
